# Native chart implementation

`ChartUtil` always renders `NativeChart`. Scatter, line, area, and bar charts share settings, axes, hover, color legends, and PNG/SVG exports. Small plots use SVG; larger plots use Canvas. Existing chart props, migration IDs, archive formats, and annotation resize behavior remain intact. `nativeVisualization` no longer selects a renderer.

Chart types, refresh, and Options live in the right-hand action bar; X, Y, and Color remain visible across the bottom. Log scales, Y-range overrides, and row limits are no longer editing controls. Transformations and limits belong in the source SQL. Previously saved values are still honored for document compatibility.

## Data and semantics

- Mosaic Core uses the document's existing CLI DuckDB session through `/api/session/compute`. There is no browser database. Charts read the prepared result view for the upstream SQL shape, preserving its native/federated query route. The view name follows the CLI's `_kavla_result_` plus first 16 SHA-256 bytes convention; changes to that backend convention must update `source.ts`.
- Missing views use the existing result restoration helper. Its restrictions on automatic BigQuery restoration remain in effect. Dirty or running upstream queries must finish before plotting.
- No default source-row cap or random sample is applied. Explicit saved `limit` values still limit the input. Cache keys include the source revision and refresh token; SQL determines the remaining cache identity, so resize and category paging can reuse statistics.
- Scatter switches from observations to full-input bins above 10,000 eligible rows. A bin contains counts, not a representative sampled row. With color grouping, strip widths show group shares and logarithmic opacity shows total count. Without grouping, a logarithmic blue color scale shows count.
- Large lines and areas keep first/last/min/max per horizontal pixel and null-separated run, retaining source order. Stacked area reduction also retains extrema of the baseline. Use `ORDER BY` in the source query to define line order.
- Bars retain the existing first-observation-per-category-and-color behavior. They do **not** silently sum raw rows. Aggregate in the source SQL when totals are intended. Positive and negative stacks accumulate separately. Repeated coordinates in areas remain observations.
- Categorical axes preserve first-occurrence order. Width-dependent category pages expose every category with explicit navigation. Continuous axes use full eligible domains. Temporal axes use UTC timestamps; numeric log axes exclude non-positive values.
- Hover operates on plotted data with spatial/grid indexes and no extra queries. Point values are retained as source strings; density bounds are approximate and clearly labeled.
- Slices and lassos on scatter and line charts support numeric, time, and category X axes. They select every source observation in the region, including duplicates and observations represented by density bins or reduced lines. Categorical selections save the keys and positions on the visible page so Explore can match the original rows.
- On bar charts the lasso selects each visible bar rectangle it overlaps. Grouped bars and positive or negative stack segments are hit individually. The saved category and series keys identify the first input row for each selected bar. Explore keeps the original row columns, including nulls, and honors the saved input limit.
- Drawing an outline on a supported plot captures a selection with the canvas Draw tool or the chart's Select shortcut. A valid completed outline transfers to `nativeSelection` in a single history transaction and its standalone draw shape is removed. A lasso can start or finish outside the plot. Kavla joins its endpoints and selects the part inside the plot. A stroke crossing multiple eligible plots goes to the first one it enters, with the frontmost chart winning ties. Capture observes newly started gestures so completed drawings restored by undo, paste, or document loading are not adopted automatically. The polygon uses the original axis domains, with stroke color, width, dash, and opacity stored alongside it. Rendering and PNG/SVG exports project it through the current plot geometry. `drawingId` is provenance, not a dependency on a live shape. Redraw replaces the outline; Clear is undoable. Legacy saved selections without an `outline` style remain readable and can be transferred using Use existing drawing, retaining their original analytical polygon.
- An open pen stroke that crosses the plot once between two different edges offers a choice of sides in the selection controls. Hover or focus previews a side. Choosing it commits the region through the same selection and Explore workflow as a lasso. Cancel keeps the stroke as a canvas drawing.
- With the Select tool, drag inside a placed lasso or slice to move it. Marks highlight during the drag. Release to refresh the count and rerun queries using that selection. Escape cancels the drag. Undo and redo refresh the linked queries with the restored position.
- The canvas has one `selected_area`. Select a supported chart to apply the same normalized outline to its plot. The selected rows use that chart’s axes, visible categories, and bar geometry. Explore creates a SQL node linked to the active chart, and Open query returns to it. Switching charts moves the dependency arrows and refreshes the same queries. Redrawing, moving, or clearing the outline refreshes linked queries and their downstream results. A cleared area returns zero rows with the source columns. Queries read the active chart and its input limit at execution. The canvas saves the active chart and outline together in page metadata. In older documents, picking a chart with a saved outline adopts that outline. Ctrl/Cmd-clicking the pink `selected_area` reference navigates to that chart.

## Mosaic optimization

- The active planner submits Mosaic SQL query objects. Compatible continuous-scatter statistics can consolidate into one backend scan across charts. Their cache keys exclude color and display dimensions, so changing color or resizing can reuse domains and counts.
- Scatter aggregation uses Mosaic SQL's `bin2d`; large lines and areas use its `m4` transform. M4 bins by display X and orders by source ordinal, with separate color/run groups. Stacked areas union upper and baseline extrema, then retrieve the original observations from a query-local materialized CTE. Equal extrema within one pixel may select a different tied observation; endpoints and extrema are preserved.
- Scatter skips duplicate-ranking and null-run windows, which are only needed for bars/stacks and lines/areas respectively. All reduction still executes in the existing CLI DuckDB session.
- The document coordinator retains Mosaic's 32 MiB LRU cache and in-flight request sharing across unrelated SQL runs. Successful SQL runs assign `meta.nativeQueryRevision`; upstream tokens qualify cache keys even when execution time and row count match an earlier run. Old documents retain their original revision identity until rerun. Backend/document/connection changes still dispose the session.
- Mosaic 0.33 consolidation drops individual request options and cannot cancel its frame queue. Signal-bearing, uncached, prioritized, and opaque string requests bypass consolidation. Canceling a chart explicitly rejects its consumer promises, including those waiting for consolidation; shared backend work may still finish for other consumers. Closing the session aborts connector work.
- Automatic preaggregation remains disabled: it targets linked point/interval filters and materialized aggregate views, neither of which is used by the current full-source chart queries or exact polygon snapshots. Enabling the flag alone would add no optimization. Compute remains read-only.
- High-cardinality categorical color still creates one group per distinct value. Mosaic's binning/M4 do not bound that group dimension. This pass does not introduce sampling, category truncation, or a top-k policy; browser memory for that case remains a separate issue.

## ECharts compatibility

Standard charts have no ECharts render path. `legacy-widget-charts.ts` is a dynamically imported compatibility module for saved Lens programs that reference ECharts. Removing that module or the ECharts packages would break those saved programs. Normal startup, standard charts, and Lens programs without ECharts references do not import it. Historical benchmark fixtures still compare with the previous renderer.

## Validation

TypeScript, the production build, and existing selection/coordinator/series/archive compatibility checks are used for validation. Direct queries through the existing test bridge additionally exercise the active planner's full-input density counts, temporal axes, paging, limits, signed stacks, duplicate area observations, empty/log inputs, and null gaps. Build-manifest inspection verifies that the legacy chart module is outside the static startup graph.

Browser appearance, pointer interactions, and actual download behavior have not been visually verified; repository instructions require permission before viewing the app.
